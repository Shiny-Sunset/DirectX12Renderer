# 企画

> `（案）` はこちらからの提案。採否を決めて `→ 採用 / 却下` を書き足す。
> **数値そのものは `GameConfig.h` に置く。**ここには「なぜそうするか」を書く。

## 一行で言うと

敵を引きつけながら味方を召喚し、群れで倒すローグライク

## ジャンル・形式

| | |
|---|---|
| ジャンル | ローグライク ＋ 指揮アクション（ピクミン型） |
| プラットフォーム | Windows（自作 C++ / DirectX 12 レンダラー） |
| 形式 | **オフライン完結。**通信なし |
| ステージ | **画面に収まる小さいステージ。カメラは固定** |
| 1 プレイの長さ | 30分くらい 10ステージぐらいで、ところどころに中ボスを入れたい |

収益化・オンライン対応は対象外。

## ★ 遊びの核：プレイヤーの仕事が 3 つある

```
配置する   召喚したい味方を選び、クリックした位置に出す
釣る       敵はプレイヤーを狙うので、引き連れて味方の群れへ誘導する
避ける     狙われているので、当たらないように動く
```

**3 つとも同じ移動操作で成立する**のが、この企画の中心。
プレイヤー自身の自動攻撃は弱く、倒すのは味方の仕事。

### プレイヤーが暇にならないための 3 つの仕掛け

| | |
|---|---|
| **敵はプレイヤーを狙う** | ヘイト値はプレイヤーが大きい。**たまに味方も攻撃する。または、広い範囲攻撃を行う。**（完全にプレイヤー固定だと味方が安全地帯になる） |
| **味方は体力が低め** | **HP 1 の使い捨てではない。**種類ごとに違い、報酬の強化で上がる |
| **同時出撃数に上限**（決定） | **場に出せる数の上限＋短いクールダウン。**報酬で上限を上げる |

> **★ 「ステージ全体で召喚できる累計回数」にはしない。**
> 使い切るのが怖くて出し渋るようになり、**マウス操作を増やしたい狙いと逆**になる。

### ★ マウス操作は「補充」ではなく「置き直し」から出る

味方が死にすぎない設計にしたので、**補充はあまり発生しない。**
代わりに操作の出どころになるのはこれ。

```
味方を置く → プレイヤーが敵を釣って群れへ誘導する → 戦う
  → 敵の位置が変わる／次の敵が来る → 群れが見当違いの場所にいる → 置き直す
```

敵はプレイヤーを追うので、**戦う場所を決めているのはプレイヤー自身。**
配置が古くなるのは、プレイヤーが動いた結果。ここが指揮の面白さになる。

> **★ ただし、上限いっぱいで味方が生きていると、もう召喚できず手が止まる。**
> **呼び戻し**（ピクミンの笛）か、**既存の味方を消して置き直す**操作のどちらかが必要。
> （案）呼び戻し。プレイヤーの周囲の味方を手元に戻し、また投げ直せる形にする。
> → 決定：召喚する味方を選んでない時は、マウスホイールで円上の範囲選択をして味方を選んで、右クリックでフリックして味方を誘導させたい。

### ★ 味方は「取り付いて継続ダメージ」

（案）味方は敵に取り付き、張り付いている間ダメージを与える（ピクミン型）。←基本的にはそうだけど、種類によっては遠距離攻撃などで近づきすぎない種類も増やしたい。

**理由：**

- **味方がその場に留まるので、戦線が目で見える。**どこが手薄かが分かり、置き直しの判断材料になる
- 体力が低めなので、「近づいて 1 回殴って死ぬ」形だと何も残らない。取り付いている間は削れている
- 敵はプレイヤーを追うので、**取り付いた味方は敵にぶら下がって運ばれていく。**
  群れが戦いに付いてくる絵になり、指揮している感じが出る

## 操作

| | |
|---|---|
| 移動 | WASD でプレイヤー自身 |
| 攻撃 | 自動。弱い |
| 味方の種類を選ぶ | （画面の左右に一覧を置いて選ぶ、一覧の上でマウスホイールを使うとスクロールする） |
| 召喚 | マウス左クリックした位置に召喚。召喚する見方を選んだ後、ステージの画面でマウスホイールを使うと召喚する数を選べる |
| （Phase 4）フリック | クリックを離した方向へ一度移動してから、敵に向かう |

> **★ フリックは Phase 1 では入れない。**
> 方向を決める操作は気持ちよさの調整が難しく、**「配置が面白いか」の判定を濁らせる。**
> まず「置いて戦う」が面白いか確かめてから足す。

## サイクル

```
ステージ開始 → 画面上の敵を全部倒す → 報酬を選ぶ → 次のステージへ画面遷移
  → …（繰り返し）→ 最終ステージのボスを倒す → クリア
```

| | |
|---|---|
| 報酬の種類 | 味方の種類の追加、同時出撃数の上限、味方のパラメータ、プレイヤー自身の強化 |
| 選び方 | 基本的に1つで、中ボスを倒したら2回報酬をもらえる |
| 死んだとき | その場で終了してやり直し |

ローグライクなので**報酬の抽選に乱数を使う。**シードを固定できる形にしておく（デバッグで同じ展開を再現するため）。

## DANGO DEFENSE から流用するもの

| | |
|---|---|
| `Enemy` の追跡 AI | **ヘイトによる標的切り替えが実装済み。**向きが逆（敵→王 が 味方→敵）になるだけ |
| `EnemyPool` | 実行中にリソースを確保しない使い回し。味方にも敵にも使える |
| `Collision` | 球と AABB、押し戻し、**グリッドによる候補の絞り込み** |
| `CharacterController` | 移動と接地 |
| `Spawner` | 時間経過で間隔が縮むスポーン |
| UI・状態遷移 | タイトル → プレイ → リザルト、文字描画 |

**カメラは固定なので作らない。**

## ★ DANGO DEFENSE と似て見える問題

```
DANGO DEFENSE   大群が画面を埋める 3D → プレイヤーが倒す
この企画        大群が画面を埋める 3D → 味方が倒す
```

核の動詞は違う（倒す／指揮する）が、**スクリーンショット 1 枚では区別が付かない。**

対策：

- **味方を 10〜20 体に抑える**（ピクミンも画面上はこの程度）。面白さのためにも必要
- 固定カメラで密度を作らない
- 味方の種類を色で明確に分ける

## 作る順番

| | 中身 | 判断すること |
|---|---|---|
| **マイルストーン 0** | ウィンドウ＋地面＋モデル 1 体＋文字 1 行 | レンダラーが独立して使えているか |
| **Phase 1** | **1 ステージだけ。味方 1 種・敵 1 種。**召喚して戦って勝つ／負ける | **自分で遊んで「もう一回」と思うか。**思わなければここで設計を変える |
| **Phase 2** | 報酬の選択とステージ遷移。ローグライクの形にする | 周回する気になるか |
| **Phase 3** | 味方と敵の種類を追加、ボス | 組み合わせが面白いか |
| **Phase 4** | フリック召喚、音、見た目の仕上げ | |

**Phase 1 で核の判定をする。**種類を増やすのはその後。
味方 1 種・敵 1 種で面白くないものは、種類を増やしても面白くならない。
